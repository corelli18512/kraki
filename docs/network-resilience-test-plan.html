Kraki Network Resilience: Test Plan

Branch test/network-resilience (based on main 985a310). Goal: iOS/Mac ↔ Head and Tentacle ↔ Head meet measurable production-grade standards under all kinds of network fluctuation. The full version is docs/network-resilience-test-plan.md in the repo.

1. Quantified "production-grade" goals

#MetricTarget
G1No lost messagesInput shown as sent/sending is delivered 100% of the time after the network recovers
G2No duplicatesThe agent receives each clientId exactly once
G3No false failuresOutages ≤60 seconds, saturated bandwidth, latency spikes: 0 "failed", no manual retry needed
G4Fast recoveryReconnect p95 ≤3 seconds; backlog send echoes and missed new messages caught up p95 ≤5 seconds
G5Dead-link detectionHalf-open connections detected within ≤30 seconds
G6No false kills0 dead-link judgments while the link carries data; one real outage reconnects exactly once
G7Order and completenessAfter recovery, contiguous by seq: no holes, reordering or duplicate bubbles
G8Honest status"Reconnecting" only after ≥2 seconds disconnected; bubble status matches reality
G9Bounded resourcesDuring a 2-hour outage, memory/disk/reconnect frequency are capped
G10Process restartsAfter the app is killed or Head/Tentacle restart, unconfirmed input is still delivered exactly once

Release gate: all protocol-level scenarios + 1000 random chaos iterations with 0 violations; all native core scenarios pass; 8-hour soak with 0 violations.

2. Gaps visible in the code (prove with tests first, then fix)

① No automatic retry. With no echo 20 seconds after sending, a message becomes "unconfirmed" and only a manual retry helps. Production has shown 13–52 second echo delays, so saturated bandwidth always triggers it — very likely the high failure rate you saw.
② Mac silently does nothing when a send is refused. Right after launch/reconnect the agent's public key is not ready yet, the send is refused, and the composer does nothing (iOS shows a failure). It should queue instead of refusing.
③ Input is not persisted on Head. Dropped when the agent is offline for more than 5 minutes; lost outright when Head restarts.
④ The app-side send queue lives only in memory. After the process is killed it comes back as "unconfirmed" but is not resent automatically.
⑤ Heartbeats misjudge under congestion. When bulk data saturates the link the pong cannot get through and the connection is kicked as dead (the direct cause of this reconnect storm).
⑥ Tentacle reconnects every 3 seconds with no backoff or jitter. Thundering herd when Head restarts; spinning during long outages.
⑦ "Reconnecting" is not debounced. Momentary drops make it flash.

5. Layers and order

Order: ① build the environment (proxy, one-command local stack, reconciler) → ② get red baseline results and numbers on unmodified main → ③ fix gap by gap, in priority order: automatic retry and tiered timeouts, queued sends, no heartbeat false kills, Head persisting input, Tentacle backoff and jitter, status debouncing, persisting the app queue — each proven by a scenario going from red to green → ④ the reduced set becomes a PR gate (triggered by change scope); chaos and soak run manually/nightly, not on every gate.

This branch contains only test infrastructure and the plan; every product fix gets its own PR with red-to-green evidence.
