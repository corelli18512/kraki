## Head 0.22.1

**Changes**
- **Signup region**: new accounts from China, Hong Kong, Macau and Taiwan still get `china`; the rest of Asia-Pacific, the Middle East, South and Central Asia and Oceania (including Palestine and the western Pacific islands) now get `us` (the Tokyo relay) instead of `china`; the Americas, Europe, Africa and unknown countries get the new `DEFAULT_SIGNUP_REGION` (main head; default `us`). A region is only assigned when it is enabled in the regions table; otherwise, and when the IP lookup fails, the account gets the main head's own region as before. Existing accounts keep their region.
- **First sign-in from the apps**: a new account whose first sign-in is the web app, iPhone or Mac app at the main relay (GitHub sign-in or a main-relay pairing link) now gets its region the same way as `kraki setup` instead of always the main head's; the main head registers the device and redirects it with `wrong_region`, and released apps reconnect to their region's relay with the device key they just registered. First sign-ins at an edge keep that edge's region.
- **Operator test accounts**: `TEST_ACCOUNTS` (main head; off when unset) lists QA accounts `{ login: "qa-…", region, tokenSha256 }` that sign in without GitHub as user `test:<login>`, pinned to their region on first sign-in. `POST /api/test-login` returns a one-time pairing link for the released web app and iOS/Mac apps; a released CLI signs in with `--auth apikey --api-key <token>`. Only token hashes are configured and tokens are never logged. Wrong tokens are throttled per IP and counted in `/internal/metrics` (`auth.testAccount.ok` / `auth.testAccount.fail`) on `/api/test-login` and, when the main head has no `apikey` auth mode, on `apikey` sign-ins and `/api/login/resolve`. `/api/test-login` returns `pairing_disabled` when pairing is off, and a non-https `TEST_LOGIN_APP_URL` (or one with a query or fragment) stops the relay at start when `TEST_ACCOUNTS` is set. Test accounts are not offered as a sign-in method. See [self-hosting](../docs/self-hosting.md#multi-region-signup-region-and-test-accounts).
- No protocol change, no database migration; edges need no update (they ignore both settings).
