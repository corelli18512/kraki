## Kraki CLI 0.39.0

**Before you update**
- **Rolling back**: this version saves the computer's replay protection in a new format. If you go back to an older Kraki later, it cannot read that file, and your paired apps are refused once for about 10–25 minutes. Updating is not affected.
- **Renamed GitHub account**: Kraki matches accounts by GitHub username. Renaming your GitHub account and signing in again counts as switching accounts: this computer's device, keys and sessions are moved aside (not deleted), and phones have to pair again.
- **A replaced daemon stays offline**: when another Kraki with the same device takes over this computer's connection (two `kraki start`s at once, or a copied `~/.kraki` folder on a second machine), the replaced daemon no longer takes the connection back in an endless loop. It stays offline until you run `kraki restart`, and `kraki status` says why. A second `kraki start` started at the same moment now fails instead of starting another daemon.
- **`KRAKI_RELAY_URL` no longer overrides the saved relay**: the daemon always connects to the relay chosen in setup. `KRAKI_RELAY_URL` only sets setup's default.

**Messages and turns**
- A message this computer cannot take (full disk, or device trust refused it, for example because the sending device's clock is more than 10 minutes off) is no longer dropped silently: up-to-date apps mark it **Not delivered** with the reason and offer Retry.
- When an agent cannot start or resume, the message fails with a reason instead of hanging, also right after a new session is created. Messages sent quickly in a row, also while offline, keep their order.
- A question the agent withdraws (timed out, cancelled or answered itself) closes at once in up-to-date apps. Claude multi-select questions carry a flag, and apps show the hint in their own language.
- Stop before any output is recorded; a stopped turn no longer adds "Failed to abort session"; cancelled permissions show as cancelled; renaming or deleting a session refused by device trust is reported instead of lost.
- **Pi**: works with Pi 1.5.2; wake runs that start after the subagent hold timed out reach the apps; an output-limit stop is a failed turn with Pi's own message; turns no longer stay "running" because a subagent widget kept repainting; grep, find and ls are available, and attached images reach Pi.
- **Codex and Claude**: compaction and interrupted turns no longer stay "running"; model lists are retried when they fail; a Claude turn waiting for background subagents settles after 30 minutes without progress; large Claude images are scaled down.
- `kraki agents` and setup point out an agent that is older than the version Kraki has been tested with.

**Connection and security**
- After a relay restart the computer no longer goes deaf to app commands until the next disconnect, and repair resends are not sent twice.
- A dead relay connection is dropped at once instead of after about 30 s; reconnect catch-up asks only for what is missing.
- Device trust: file locks cannot be taken over while another process writes them; on Windows, concurrent writers no longer fail with `EPERM`; renamed apps show their new name; a forward clock jump no longer locks out a day of messages.
- Only Head-format sign-in challenges are signed; payloads reassembled from fragments are credited to their real sender; `wrong_region` redirects are followed only to trusted relays; oversized payloads and multicasts are split or refused instead of stalling the link.
- The operating system's trusted root certificates are used, so a company proxy with its own certificate works.

**Command line**
- `kraki status` and `kraki stop` see a daemon whose worker is restarting (they used to say "stopped" / "not running"); `kraki start` waits for the first relay connection before showing the connect code and says why it refuses.
- `kraki config reset` restarts a running daemon and keeps the computer's name.
- `kraki setup --headless` accepts `--agent pi`, validates `--relay` (an `https://` address is saved as `wss://`), and asks for the key on an API-key relay. `setup --json` output stays clean and exits when done.
- `kraki update` on npm installs into the running install and checks the result; failed commands exit non-zero.
- `install.sh` restarts an older running daemon after updating, cleans up after Ctrl+C, and says clearly whether it changed your PATH. The README explains how to uninstall.
- A full disk no longer crash-loops the daemon; log lines over 1 MiB are kept; logs record lengths instead of titles and prompt text; the Linux sleep inhibitor ends with the daemon.
